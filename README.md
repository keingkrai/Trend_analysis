## 🧭 ภาพรวม

ระบบทำงานคล้ายทีมวิจัยตลาด: แยกทีมเก็บหลักฐาน 3 สายที่ไม่ปนกัน ให้แต่ละสายสรุปเทรนด์ของตัวเอง แล้วค่อยรวมกันที่ชั้นพยากรณ์
คัดเทรนด์ที่กำลังโต ดูว่าตลาดมีสินค้ารองรับหรือยัง และสรุปเป็นรายงาน — **ตัวเลขตัดสินด้วยกฎตายตัว ส่วน LLM ทำงานด้านภาษา**

```mermaid
flowchart LR
    subgraph S["①-⑤ หลักฐาน 3 สาย (แยกกันอิสระ)"]
        P["Paper<br/>ScienceDaily · MDPI · OpenAlex · PubMed Central"]
        SO["Social<br/>Pantip · Reddit · YouTube"]
        N["News<br/>ข่าวไทย + สากล (RSS · Google News)"]
    end
    P --> K
    SO --> K
    N --> K
    K["15 เทรนด์ + คีย์เวิร์ด<br/>(สายละ 5)"] --> F["⑦ พยากรณ์ Google Trends<br/>4 โมเดล → Z_Delta"]
    F --> AG["⑧-⑨ สรุประดับหมวด / ภาพรวม"]
    F --> R["⑥ Rank Score"]
    R --> H["⑪ จุดเด่น + คัด Top N<br/>(เหนือค่ากลางตลาด ไม่เกิน N · ค่าเริ่มต้น 10)"]
```

### สายหลักฐาน (①-⑤)

ทั้ง 3 สายใช้โครงเดียวกัน ต่างกันแค่แหล่งข้อมูลและภาษาที่ใช้ค้น จึงเทียบกันได้ตรงๆ

| สาย | แหล่งข้อมูล | ตอบคำถาม |
|---|---|---|
| **Paper** | ScienceDaily, MDPI, OpenAlex, PubMed Central | กลไกและเทคโนโลยีอะไรกำลังมา |
| **Social** | Pantip, Reddit, YouTube | ผู้บริโภคเจอปัญหาอะไร พูดถึงอะไร |
| **News** | ข่าวไทย + ข่าวสากล (RSS ใน `config/rss_feeds.json` + Google News) | ตลาด/แบรนด์/กฎเกณฑ์ขยับไปทางไหน |

ขั้นตอนในแต่ละสาย: LLM สร้างคำค้น → รวบรวมบทความ → LLM เลือกชิ้นที่เกี่ยวข้อง → เขียนรายงานพร้อมอ้างอิง `(Ref N)` →
สกัด triplet ทีละเอกสาร **พร้อมประโยคหลักฐานที่โค้ดตรวจว่ามีอยู่จริง** → สร้างกราฟและจัดกลุ่ม (Louvain โหวต 20 รอบ) →
ตั้งชื่อเทรนด์ + ให้คะแนน Longevity → แตกคีย์เวิร์ดสำหรับค้น Google Trends — เก็บ 5 เทรนด์ต่อสาย

### ชั้นพยากรณ์และจัดอันดับ (⑦ ⑧-⑨ ⑥)

- **⑦ พยากรณ์** — ดึง Google Trends ทั่วโลกผ่าน SerpAPI แปลงเป็น z-score รายเดือน พยากรณ์ด้วย 4 โมเดล
  (Holt-Winters, Linear Regression, Random Forest, XGBoost) เลือกโมเดลจากความคลาดเคลื่อนบนช่วง holdout 6 เดือน
  แล้วคำนวณ **Z_Delta** = ค่าเฉลี่ยที่พยากรณ์ − ค่าปัจจุบัน สถานะตั้งด้วยเกณฑ์ตายตัว
  (> 0.8 Major Breakout, > 0.2 Rising, < −0.2 Fading, นอกนั้น Stable)
- **⑧-⑨ สรุประดับหมวด** — รวม Z_Delta เป็นภาพรวมต่อสายและทั้งหมด (เป็นผลสรุป ไม่มีขั้นอื่นอ่านต่อ)
- **⑥ Rank Score** (🆕 2026-09-30, 🆕 2026-10-02 ปีที่ 2, 🆕 2026-10-19 ปีที่ 3) — **คะแนนการเติบโตปีที่ 3** (ระยะสั้น = `common/horizons.SHORT_YEAR`) จาก `growth_score.py`: ความแรง = ค่าเฉลี่ยการค้นหาที่คาดในปีนั้น ÷
  ค่าเฉลี่ย 12 เดือนล่าสุด ผสมอันดับ momentum (การโตปีที่แล้ว) กับ RandomForest ที่ฝึกจากทุกคีย์เวิร์ดในอดีต ให้คะแนนเป็น
  percentile เทียบคีย์เวิร์ดทั้งหมดในรอบ (0.5 = ค่ากลางตลาด) คำนวณปีที่ 1-5 - backtest 2016-2022 ได้ Spearman ≈ 0.40-0.52
  (Z_Delta เดิม −0.20) ไม่มีโบนัสจำนวนสายแล้ว (ใช้ตัดสินกรณีเท่ากัน) ฝึกด้วยข้อมูลถึง `LAST_TRUSTED_MONTH` (มิ.ย. 2025)
  เพราะข้อมูล cat=0 กระโดดตั้งแต่ ส.ค. 2025 **ตอนนี้ใช้โมเดลอย่างเดียว** (`growth_score.BLEND_MOMENTUM = False`) เพราะช่วง
  กระโดดทำให้ momentum เพี้ยน คะแนนเทรนด์ = percentile ของ % ที่คาดของเทรนด์ ระดับกับ % ในรายงานจึงตรงกัน เปิดแบบผสมกลับเมื่อ
  ข้อมูลถึง ก.ค. 2027 (โปรแกรมเตือนให้เอง) กราฟหน้าเทรนด์แสดงระดับที่คาดปีที่ 1-5 พร้อมแถบ 80% จาก backtest (คลาดเฉลี่ย
  6% / 9% / 12% / 16% / 20%) และปรับคะแนน Longevity ของเทรนด์ที่ยืนยันข้ามสาย — **รันหลัง ⑦ เพราะใช้
  ค่าการค้นหารายเดือน (step5a)**

### ชั้นอุปทาน (⑪ ⑫ ⑬)

- **⑪ จุดเด่น + Top N** — เดินตามอันดับ ⑥ ให้ LLM สกัดจุดเด่น (Means-End Chain / JTBD) และจัดประเภทเทรนด์
  ข้ามเทรนด์ประเภทช่องทาง/พฤติกรรมการซื้อ หรือที่ไม่มีข้อความให้จับคู่ แล้วเลื่อนอันดับถัดไปขึ้นมา **แต่หยุดที่ค่ากลางตลาด**
  (เฉพาะเทรนด์ที่คะแนนปีที่ 3 ถึง `GROWTH_LINE` = 0.5) หรือครบ N ถ้าถึงก่อน - **N คือเพดาน จำนวนที่ได้จริงมักน้อยกว่า**
  (รอบ snapshot ตอนที่ยังใช้ปีที่ 2: 15 เทรนด์ ขอ 10 ได้ 6 เทรนด์สินค้า; รอบ 082438 ที่ปีที่ 3 ได้ 8) · ตรวจเพิ่มจนรู้ Top 5 ที่จับคู่ได้ของปีที่ 3 และปีที่ 5
  บันทึกใน `checked_trends` / `extra_profiles` - ⑫ ⑬ ยังอ่านแค่ `profiles`
  ชุด `profiles` นี้คือชุดสินค้าชุดเดียวที่ ⑫ ⑬ และรายงานใช้ร่วมกัน - เทรนด์เหนือเส้นที่ ⑪ ข้าม (ช่องทาง/ข้อมูลไม่พอ) อยู่ใน
  `excluded_trends` และรายงาน ⑯ เอามาทำหน้าอธิบาย (ดูหัวข้อ "รายงาน PDF (⑯)")
- **⑫ จับคู่สินค้า** — แปลงจุดเด่นเทรนด์ (`query`) และข้อมูลสินค้า Konvy (สินค้าความงาม ~27,000 SKU) (`passage`) เป็นเวกเตอร์ 2,048 มิติ
  เรียงด้วย cosine similarity เก็บ 15 อันดับแรกต่อเทรนด์ และให้ LLM เขียนเหตุผลสั้นๆ ให้ 5 อันดับแรก
  และแยกหมวด (`by_category`, ไม่ใช้ LLM): ดูว่าสินค้า 1% แรกที่ใกล้ที่สุดอยู่หมวดไหน (**Level 2 ของ Euromonitor** ตาม
  `product/product_category.csv` และตลาดกรองเหลือ **L1 = Beauty and Personal Care** ~8,800 SKU) เก็บ 4 หมวดที่มีมากสุด หมวดละ 3 ชิ้น
  (หมวดที่มีสินค้าใน 1% นั้นไม่ถึง 3 ชิ้นไม่ได้คอลัมน์ ถ้าเหลือไม่ถึง 4 หมวด หมวดที่ใหญ่ที่สุดแตกตามชนิดสินค้า Level 4 เช่น "Skin Care · Serum") -
  รายงาน PDF ใช้ทำหน้าสินค้า (หมวดของสินค้าแต่ละชิ้นจัดโดย LLM ล่วงหน้า ดู `product/classify_products_llm.py`)
  รอบที่รันก่อนมีการแยกหมวด เติมได้ด้วย `validate_at_scale_nvidia.py --categories-only` (NVIDIA เทรนด์ละ 1 ครั้ง ไม่แตะผลเดิม)
- **⑬ ค้นหาแบรนด์** — ดูว่าสินค้าของแบรนด์ที่ระบุอยู่ตรงไหนของแต่ละเทรนด์ (Top 5 ต่อเทรนด์)

### รายงาน (⑭-⑮)

วิเคราะห์แรงขับ 6 ด้าน (STEPIC: Society, Technology, Environment, Policy, Industry, Creativity) สังเคราะห์รวม
(ข้อมูลพยากรณ์ที่ป้อนเข้า STEPIC เป็นการเติบโตที่คาดต่อเทรนด์จาก ⑥ - ไม่ใช่ z-score) แล้วประกอบเป็น Master Report ที่มีรายงาน 3 สาย ผลพยากรณ์ จุดเด่นเทรนด์ และสินค้าที่จับคู่ได้ เรียงตามอันดับของ ⑪ (การเติบโตที่คาดในปีที่ 3)

```bash
python tool/phase5_report/run_stepic_report.py --from-saved    # ประกอบ md ใหม่จากผล STEPIC ที่บันทึกไว้ ไม่เรียก LLM
python tool/phase5_report/run_stepic_report.py --reintegrate   # ใช้ผล 6 มิติเดิม เรียก LLM เฉพาะขั้นสังเคราะห์รวม
python tool/phase5_report/run_stepic_report.py --narrative     # ใช้ผล STEPIC เดิมทั้งชุด เรียก LLM เฉพาะข้อความต่อเทรนด์
```

### รายงาน PDF (⑯)

รายงานแบบสไลด์ 16:9 (แบบรายงาน Trend Hunter) **2 ไฟล์: ภาษาอังกฤษและภาษาไทย** เนื้อหาและจำนวนหน้าเหมือนกัน ประกอบจากผลทุกขั้นของรอบ: ปก, Report Summary, Takeaway,
Market Overview (ค่ากลางที่คาดปีที่ 3 / ปีที่ 5 + บทสรุปตลาด + จำนวนเทรนด์ที่สูงกว่าระดับตลาด "8 จาก 15"), Top 5 ระยะสั้น (ปีที่ 3) เทียบระยะยาว (ปีที่ 5)

(ปีที่ 1-5 แบ่งหัวเป็นระยะสั้น = ปี 1-3 และระยะยาว = ปี 4-5 เส้นประที่ระดับตลาด - หน้าแบบสะสมเลิกแล้ว, หน้า CAGR / YoY แยกเลิกแล้วตั้งแต่ 2026-10-19), STEPIC, Personas,
Trend Drivers (heatmap เทรนด์ x แรงขับ STEPIC 6 ด้าน + persona 3 กลุ่ม),
แล้ว**หน้ารายละเอียดเทรนด์ละ 2 หน้า เฉพาะเทรนด์เหนือค่ากลางตลาดในปีที่ 3** (เทรนด์ใต้เส้นอยู่เฉพาะในตารางและกราฟภาพรวม)
(หน้า 1: % ที่คาดปีที่ 3 / ปีที่ 5 เป็นเฉลี่ยต่อปี / 12 เดือนที่ผ่านมา / แหล่งที่ยืนยัน + Longevity, กราฟพยากรณ์ปีที่ 1-5 (🆕 2026-10-19
เส้นสีน้ำเงิน = เติบโตเฉลี่ยต่อปี แท่งเทา = เปลี่ยนเทียบปีก่อนหน้า ตัวเลข YoY อยู่ใต้ชื่อปี - แทนกราฟประวัติการค้นหา 3 ปี + แถบ 80%
ซึ่งยังใช้ในหน้าวิธีการ `charts.history_chart_svg`), Means-End 3 บรรทัด (จุดต่าง / ประโยชน์ / ความรู้สึก)
+ คำถาม Workshop; หน้า 2: สินค้า Konvy ที่ใกล้ที่สุดแยกตามหมวดหลักของเทรนด์ และช่วงราคาต่อปริมาณ
- รอบที่ผล ⑫ ยังไม่มีข้อมูลหมวดใช้หน้าสินค้าแบบเดิม 5 ชิ้น) · 🆕 2026-10-15 เทรนด์ที่ ⑪ ตัดสินแล้วว่าไม่พบสินค้าในตลาด
(ช่องทาง/พฤติกรรมการซื้อ หรือข้อมูลไม่พอ) **ถูกเอาออกจากรายงาน ⑯ ทั้งเล่ม** - ไม่มีหน้า ไม่มีแถวในตารางภาพรวม CAGR + YoY ไม่นับ

จำนวนเทรนด์ที่มีหน้าจึงไม่ใช่ N ของ ⑪ ตรงๆ (รอบ snapshot: 15 เทรนด์ -> 13 เทรนด์ในรายงาน, 6 หน้ารายละเอียด)
และภาคผนวกวิธีการ — เฉพาะเทรนด์ ไม่มีหน้าเทียบแบรนด์ (⑬ แยกจาก PDF) ตัวเลขทุกตัวมาจากไฟล์ผลรัน ไม่แสดงว่าเทรนด์มาจากสายไหน
**ระยะสั้น/ระยะยาว** = % การค้นหาที่คาดปีที่ 3 / ปีที่ 5 เทียบ 12 เดือนล่าสุด (🆕 2026-10-19 ระยะสั้น 2 -> 3 ปี) (🆕 2026-10-02 เดิมเป็น 4 ระดับ "เร็ว/ช้ากว่าตลาด"
ของปีที่ 1 / 3) สีแท่ง = คะแนนเทียบค่ากลางของคีย์เวิร์ดทั้งหมดในรอบ (เหนือ/ใต้) - 🆕 2026-09-30 ไม่มี Z_Delta, กราฟพยากรณ์
z-score และกลุ่มกลยุทธ์ Invest / Harvest / Build / Watch แล้ว Longevity (70+ / 55-69 / 40-54 / < 40) ยังแสดงในหน้าเทรนด์
เป็นข้อมูลความยั่งยืนประกอบ และที่หลักฐานไม่พอแสดง "Not enough evidence" แยกต่างหาก
LLM ใช้แค่งานภาษา: ฉบับอังกฤษเรียบเรียงจุดเด่นเทรนด์ (⑪ เป็นภาษาไทย) เป็นภาษาอังกฤษ ฉบับไทยเขียนข้อความต่อเทรนด์เป็นภาษาไทย
และแปลบทวิเคราะห์ภาษาอังกฤษ (Takeaway, STEPIC, Personas, เหตุผลจับคู่สินค้า ฯลฯ) ย่อโปรไฟล์ ⑪ เป็น Means-End 3 บรรทัด (ได้ทั้ง 2 ภาษา
ในการเรียกเดียว - ไม่ผ่านการตรวจใช้ย่อหน้า Trend/Insight แทน) - ทั้งหมด cache ไว้ รันสร้าง PDF ซ้ำจึงไม่เรียก LLM อีก
**ยกเว้น 1 จุดที่ LLM ตัดสิน:** หน้า Trend Drivers ให้ LLM บอกระดับความเชื่อมโยง 0/1/2 ต่อช่อง (`trend_links.py`) พร้อมหลักฐาน
ช่องที่ไม่มีหลักฐานถูกปรับเป็น 0 ตัวเลขอื่นในรายงานไม่ใช้ผลนี้ และไม่มี LLM ก็ไม่มีหน้านี้
ฉบับไทยคงชื่อเทรนด์ คีย์เวิร์ดค้นหา และชื่อแบรนด์/สินค้าเป็นภาษาอังกฤษ ปีเป็น ค.ศ. ข้อความตายตัวของทั้ง 2 ภาษาอยู่ที่
`tool/phase6_pdf_report/i18n.py`
โลโก้และชื่อบริษัทตั้งที่ `config/report_branding.json`

### รายงานแบรนด์ x เทรนด์ (⑰)

รายงาน **1 ไฟล์ต่อ 1 แบรนด์ลูกค้า** (อังกฤษ + ไทย, 16 หน้า) แยกจากรายงานเทรนด์ สร้างต่อจาก ⑬ ของแต่ละแบรนด์ในลูปถามแบรนด์
(ทั้งโหมด 1 และโหมด 2): ปก → สรุปผู้บริหาร (สินค้าของแบรนด์บน Konvy + จำนวนเทรนด์แต่ละระดับ + ประเด็นสำคัญ 3 ข้อ) →
Trend Fit Matrix (แรงส่งของเทรนด์ x อันดับของสินค้าที่ใกล้ที่สุดของแบรนด์ แบ่ง 4 ช่อง: ปกป้อง / สร้างใหม่ / รักษาไว้ / เฝ้าดู) →
ตารางภาพรวม → เทรนด์ละ 1 หน้า (ตาราง **top 5 สินค้าใกล้เทรนด์ที่สุดของตลาดทั้งหมด** + สินค้าของแบรนด์ 1-3 ชิ้นต่อท้ายพร้อม
**อันดับในตลาด** ถ้าสินค้าแบรนด์ติด top 5 จะไฮไลต์แถวนั้นในตาราง; top 5 มาจากผล ⑫ ชุดเดียวกับรายงานเทรนด์ อันดับสินค้าแบรนด์มาจาก ⑬ -
จำนวนแถวตั้งที่ `market_top_n` / `products_per_trend` ใน `config/brand_report.json`; เทรนด์ที่ไม่พบสินค้าในตลาด
ไม่ถูกนำมาเทียบ - ตั้งแต่ 2026-10-15 ถูกตัดตั้งแต่ ⑯ แล้ว `report_data.product_trends` จึงเป็นแค่ตัวกันซ้ำ) → โอกาสพัฒนาสินค้า (เทรนด์ในช่อง สร้างใหม่) → ภาคผนวก

**ระดับความพร้อมวัดจากอันดับจริงในตลาด** ของสินค้าที่ดีที่สุดของแบรนด์ (นำตลาด 1-25, แข่งขันได้ 26-100, ตามหลัง 101-500,
ช่องว่าง เกิน 500 หรือไม่มีสินค้า - ปรับได้ที่ `config/brand_report.json`) ไม่ใช้ tier ของ ⑬ เพราะ tier วัดจาก percentile
ของสินค้าที่ดีที่สุดซึ่งแทบเกิน 67 เสมอเมื่อแบรนด์มีหลาย SKU (รอบ 082438 ได้ "ตามทัน" ครบ 50/50 คู่) - เกณฑ์ตั้งขึ้นเอง
ยังไม่ได้เทียบกับการตัดสินของคน LLM ใช้แค่แปลเหตุผลจับคู่สินค้าของแบรนด์เป็นไทย (cache ต่อแบรนด์) ข้อความเทรนด์ใช้ cache ของ ⑯

### รายงานหมวด x ระดับราคา (⑱) — รวมเข้า ⑰ แล้ว (🆕 2026-10-14)

**⑱ ไม่ถูกสร้างแยกอีก** - หน้าสินค้าต่อเทรนด์ของ ⑰ (หน้าที่ 2 ของแต่ละเทรนด์) ใช้หน้าตาเดียวกับหน้าเทรนด์ของ ⑱ เดิม: 3 กลุ่มราคาต่อปริมาณ (ต่ำ/กลาง/สูง) แต่ละกลุ่มมี top 5 + สินค้าที่ดีที่สุดของแบรนด์ พร้อมอันดับ / % แรกของกลุ่ม / อันดับทั้งร้าน (ข้อมูลจาก `brand_category_data.build_category_context` ชุดเดียวกับที่ ⑱ ใช้ - `category_fit` ของ ⑬) ข้อความ/CSS ของหน้านั้นอยู่ใน `brand_category_i18n.trend_page_strings` (คีย์ `cp_*`) และ `templates/brand_trend_page.css`; ตารางภาพรวมหมวด x กลุ่มราคาและสรุปผู้บริหารของ ⑱ ไม่ได้ย้ายมา. สคริปต์ `build_brand_category_report.py` ยังอยู่ (สร้าง ⑱ แยกเองได้) แต่ `main.py` ไม่เรียกแล้ว; ไฟล์ ⑱ เดิมของรอบ ที่เคยสร้างย้ายไป `output/_backups/brand_report_merge_20261014/<รอบ>/`. ข้อความด้านล่างเป็นประวัติของ ⑱ เดิม

🆕 2026-10-05 รันลูกค้า 1 ครั้งได้ **2 รายงาน** (ฉบับละ อังกฤษ + ไทย): ⑰ เทียบสินค้ากับตลาดทั้งร้าน และ ⑱ เทียบ**ในหมวดของเทรนด์ แล้วแบ่งตามช่วงราคาของแบรนด์เอง**
(ข้อเสนอแนะ: ซีรัมของแบรนด์ไม่ควรต้องแข่งกับกันแดดหรือเครื่องสำอางในอันดับเดียว) สร้างต่อจาก ⑰ ในลูปถามแบรนด์ทั้งสองโหมด:
ปก → สรุปผู้บริหาร (สินค้าแบรนด์แยกหมวด + จุดแข็ง + เทรนด์ที่แบรนด์ไม่มีสินค้าในหมวด) → ตารางทุกเทรนด์ (หมวดหลัก, อันดับในหมวด, อันดับในแต่ละระดับราคา) →
เทรนด์ละ 1 หน้า (3 ระดับราคา: top 5 ของ "หมวด ∩ ระดับราคา" + สินค้าที่ดีที่สุดของแบรนด์ในระดับนั้นพร้อมอันดับ เช่น "#11 จาก 1,151 (1% แรก)" และอันดับในตลาดทั้งร้าน) → ภาคผนวก

วิธีคิด (โค้ดอยู่ที่ `phase3_supply_layer/price_tiers.py` เรียกจาก ⑬ ใช้ similarity ชุดเดียวกับที่ ⑬ คำนวณอยู่แล้ว ไม่เรียก LLM เพิ่ม):
1. เทรนด์ → หมวด L2 หลัก = หมวดที่มีสินค้าใน 1% แรกของตลาดมากที่สุด (ตรรกะเดียวกับ `category_breakdown.py` ของ ⑫)
2. สินค้าของแบรนด์ในหมวดนั้น → แบ่ง**ราคาของแบรนด์เอง**เป็น ≤ 3 ระดับเท่าๆ กัน (แต่ละระดับมีสินค้าของแบรนด์ ≥ 2 ชิ้น เส้นแบ่งอยู่กึ่งกลางระหว่างราคาที่ติดกัน)
   ช่วงราคารวมจำกัดที่ [ต่ำสุด, สูงสุด] ของแบรนด์ — สินค้าตลาดที่ถูก/แพงกว่านี้ไม่ถูกเทียบ
3. อันดับในระดับราคา ≤ อันดับในหมวด ≤ อันดับในตลาดทั้งร้านเสมอ (กลุ่มเทียบเล็กลง) แบรนด์ที่ไม่มีสินค้าในหมวดหลักแสดง top 5 ของหมวดทั้งช่วงราคา + ข้อความแจ้ง
ข้อจำกัด: ชุดของขวัญ/เซ็ตรวมอยู่ในหมวด (ดันระดับราคาสูง), สินค้าไม่มีราคาไม่ถูกเทียบ, L2 กว้าง (Skin Care รวมซีรัม/มาสก์/คลีนเซอร์), แบรนด์ที่มีสินค้าในหมวดน้อยได้ 1-2 ระดับ
(ถ้าสินค้าทุกชิ้นราคาเดียวกัน ระดับเดียวเทียบเฉพาะสินค้าราคานั้น)

ผล ⑬ ของรอบเก่าที่ยังไม่มี `price_tiers` เติมย้อนหลังได้โดยไม่รัน ⑬ ทั้งชุด (ไม่เรียก LLM, embed เทรนด์ใหม่ ~1 เรียก/เทรนด์) แล้วสร้างรายงาน:

**ตรวจภาษาและทดสอบผู้อ่าน (ขั้น E, 2026-10-12)** - ตัวตรวจอัตโนมัติ + ชุดทดสอบกับผู้อ่านจริง:

```bash
python tool/phase6_pdf_report/lint_report_language.py                       # ทุกรอบใน output/ (ข้อความตายตัว + ข้อความ LLM + PDF)
python tool/phase6_pdf_report/lint_report_language.py --run <รอบ> --md lint.md --no-pdf
python tool/phase6_pdf_report/reader_test.py sheet --lang th                # สร้างใบคำถาม/เฉลย/ใบตอบ -> output/_reader_test/
python tool/phase6_pdf_report/reader_test.py score answers.csv --lang th --md result.md
```

- `lint_report_language.py` ไม่เรียก API: **ERROR** = คำต้องห้ามนอกภาคผนวก (YoY, SKU, โมเดลภาษา, similarity ...), ศัพท์ pipeline หลุด (⑬, `--flag`, `*.py`, `{ตัวแทนค่า}`, None/nan);
  **WARN** = ประโยคอังกฤษยาวเกิน 35 คำ / ไทยติดกันเกิน 110 ตัวอักษร / คำอังกฤษทั่วไปในข้อความไทยที่ไม่ใช่ชื่อหรือส่วนผสม (รายการอนุญาตมาจากชื่อเทรนด์/สินค้า/แบรนด์ของรอบ + `BASE_ALLOW`)
  ข้ามกติกาในภาคผนวก (คีย์ `method_*`/`m_*`/`notes_*` และหน้าที่ขึ้นต้น "ภาคผนวก"/"Appendix"); ตรวจเฉพาะเทรนด์ที่อยู่ในรอบ (ไม่ตรวจรายการค้างใน cache) และเฉพาะ PDF ที่ pipeline สร้าง; exit 1 เมื่อมี ERROR (`--strict` นับ WARN ด้วย)
- ผลรอบล่าสุด (2026-10-12): ข้อความตายตัว 0 ERROR / 0 WARN, PDF ทุกรอบ 0 ERROR; WARN ที่เหลือเป็นข้อความที่ LLM เขียน (ชื่อสารเคมีอังกฤษ ฯลฯ) ให้ DA ตัดสิน
- `reader_test.py`: คลังคำถามปรนัย 16 ข้อ (⑯ 6 / ⑰ 5 / ⑱ 5) ถามความหมายของข้อความหลักในรายงาน (ตัวเลข % ปีที่ 2, "ตรงเทรนด์อันดับ n", ราคาต่อปริมาณต่ำ/กลาง/สูง, เกรดภาพรวม, "ติด x% แรก (อันดับ n)" ฯลฯ)
  อ้างข้อความจริงจากตารางข้อความจึงตามไปเองเมื่อแก้ถ้อยคำ ผู้อ่าน 3-5 คน (ไม่ใช่นักวิเคราะห์) คนละ ~15 นาที ไม่อธิบายระหว่างทำ -> กรอกใบตอบ CSV (1 แถว/คน)
  ผ่านเมื่อตอบถูกรวม ≥ 80% และทุกข้อ ≥ 60% ข้อที่ไม่ผ่านบอกตัวลวงที่คนเลือกมากสุด + คีย์ข้อความที่ต้องเขียนใหม่ (`trend.*`, `brand.*`, `category.*`, `unit.*`)
  **ยังไม่ได้ทดสอบกับผู้อ่านจริง** - ต้องให้ DA/ทีมหาผู้อ่านและรันรอบแรก

### รายงาน PDF (⑯)

รายงานแบบสไลด์ 16:9 (แบบรายงาน Trend Hunter) **2 ไฟล์: ภาษาอังกฤษและภาษาไทย** เนื้อหาและจำนวนหน้าเหมือนกัน ประกอบจากผลทุกขั้นของรอบ: ปก, Report Summary, Takeaway,
Market Overview, Trend Map (Z_Delta เทียบจำนวนสายที่ยืนยัน), Rank Trajectory (bump chart อันดับรายปี), STEPIC, Personas, แล้วเทรนด์ละ 3 หน้า (Trend/Insight + กราฟพยากรณ์ → Workshop Question → สินค้า Watsons
ที่ใกล้ที่สุด) และภาคผนวกวิธีการ — เฉพาะเทรนด์ ไม่มีหน้าเทียบแบรนด์ (⑬ แยกจาก PDF) ตัวเลขทุกตัวมาจากไฟล์ผลรัน ไม่แสดงว่าเทรนด์มาจากสายไหน
LLM ใช้แค่งานภาษา: ฉบับอังกฤษเรียบเรียงจุดเด่นเทรนด์ (⑪ เป็นภาษาไทย) เป็นภาษาอังกฤษ ฉบับไทยเขียนข้อความต่อเทรนด์เป็นภาษาไทย
และแปลบทวิเคราะห์ภาษาอังกฤษ (Takeaway, STEPIC, Personas, เหตุผลจับคู่สินค้า ฯลฯ) - ทั้งหมด cache ไว้ รันสร้าง PDF ซ้ำจึงไม่เรียก LLM อีก
ฉบับไทยคงชื่อเทรนด์ คีย์เวิร์ดค้นหา และชื่อแบรนด์/สินค้าเป็นภาษาอังกฤษ ปีเป็น ค.ศ. ข้อความตายตัวของทั้ง 2 ภาษาอยู่ที่
`tool/phase6_pdf_report/i18n.py`
โลโก้และชื่อบริษัทตั้งที่ `config/report_branding.json`

### รายงานแบรนด์ x เทรนด์ (⑰)

รายงาน **1 ไฟล์ต่อ 1 แบรนด์ลูกค้า** (อังกฤษ + ไทย, 16 หน้า) แยกจากรายงานเทรนด์ สร้างต่อจาก ⑬ ของแต่ละแบรนด์ในลูปถามแบรนด์
(ทั้งโหมด 1 และโหมด 2): ปก → สรุปผู้บริหาร (สินค้าของแบรนด์บน Watsons + จำนวนเทรนด์แต่ละระดับ + ประเด็นสำคัญ 3 ข้อ) →
Trend Fit Matrix (แรงส่งของเทรนด์ x อันดับของสินค้าที่ใกล้ที่สุดของแบรนด์ แบ่ง 4 ช่อง: ปกป้อง / สร้างใหม่ / รักษาไว้ / เฝ้าดู) →
ตารางภาพรวม → เทรนด์ละ 1 หน้า (สินค้าของแบรนด์ 3 อันดับแรก เทียบสินค้าเจ้าตลาด) → โอกาสพัฒนาสินค้า (เทรนด์ในช่อง สร้างใหม่) → ภาคผนวก

**ระดับความพร้อมวัดจากอันดับจริงในตลาด** ของสินค้าที่ดีที่สุดของแบรนด์ (นำตลาด 1-25, แข่งขันได้ 26-100, ตามหลัง 101-500,
ช่องว่าง เกิน 500 หรือไม่มีสินค้า - ปรับได้ที่ `config/brand_report.json`) ไม่ใช้ tier ของ ⑬ เพราะ tier วัดจาก percentile
ของสินค้าที่ดีที่สุดซึ่งแทบเกิน 67 เสมอเมื่อแบรนด์มีหลาย SKU (รอบ 082438 ได้ "ตามทัน" ครบ 50/50 คู่) - เกณฑ์ตั้งขึ้นเอง
ยังไม่ได้เทียบกับการตัดสินของคน LLM ใช้แค่แปลเหตุผลจับคู่สินค้าของแบรนด์เป็นไทย (cache ต่อแบรนด์) ข้อความเทรนด์ใช้ cache ของ ⑯

## ▶️ การใช้งาน

### รันแบบโต้ตอบ

```powershell
python main.py
```

เลือกโหมดตอนเริ่ม:

1. **รันเทรนด์ทั้งชุด** — ถามหัวข้อ, จำนวนปีที่พยากรณ์, จำนวน Top N แล้วรันทุกขั้นตามลำดับ จบแล้วถามว่าจะรัน ⑩ ไหม
   และถามชื่อแบรนด์สำหรับ ⑬ ได้หลายแบรนด์ต่อเนื่อง
2. **ค้นหาแบรนด์ในเทรนด์** — เลือกรอบที่มีอยู่แล้ว แล้วรันเฉพาะ ⑬ ไม่ต้องรันเทรนด์ใหม่
3. **อัปเดตรอบเดิมด้วย Google Trends ล่าสุด** (🆕 2026-10-07) — เลือกรอบที่มีอยู่แล้ว ระบบสร้าง**รอบใหม่** (โฟลเดอร์ใหม่ รอบเดิมไม่ถูกแตะ)
   ที่ใช้เทรนด์ + คีย์เวิร์ดของรอบเดิม (สำเนาผล ①-⑤) แล้วรัน ⑦ → ⑧-⑨ → ⑥ → ⑪ → ⑫ → ⑭-⑮ → ⑯ และ ⑬ ⑰ ⑱ ของแบรนด์ที่รอบเดิม
   มีผลอยู่ (แล้วถามแบรนด์เพิ่มได้) - หัวข้อ / จำนวนปี / Top N ใช้ของรอบเดิม, ⑪ ใช้จุดเด่นเดิม และ ⑫ ใช้เหตุผลจับคู่สินค้าเดิม
   รายงานจึงต่างจากรอบเดิมแค่ส่วนที่มาจาก Google Trends (อันดับ, % ที่คาด, Top N อาจเปลี่ยน - เทรนด์ที่เพิ่งเข้า Top N ยังเรียก LLM
   ตามปกติ) ไม่มีหน้าเทียบกับรอบเดิม ไม่รัน ⑩ · ก่อนเริ่มแสดงเดือนสุดท้ายของข้อมูลรอบเดิม จำนวนคีย์เวิร์ด (= SerpAPI search ที่ใช้)
   แล้วถามยืนยัน · ที่มาบันทึกใน `_manifest.json` ช่อง `_refresh` (`refreshed_from`, `evidence_collected` = วันเก็บหลักฐาน 3 สายจริง)
   และรายการรอบในเมนูมีป้าย `[อัปเดตจาก <รอบเดิม>]` · วันที่บนรายงานเป็นวันที่อัปเดต · แผนฟรีของ SerpAPI (250 search/เดือน)
   อัปเดตรอบ 082438 (~145 คีย์เวิร์ด) ได้ราวเดือนละ 1 รอบ · Google Trends ปรับสเกลใหม่ทุกครั้งที่ดึง ค่าเดือนเก่าจึงขยับได้เล็กน้อยด้วย

## 🔁 ความคลาดเคลื่อนและข้อจำกัด

- **LLM ให้ผลต่างกันได้ในแต่ละรอบ** — ชื่อเทรนด์และคีย์เวิร์ดอาจไม่เหมือนเดิมแม้ใช้หัวข้อเดิม ลดผลนี้ด้วย `temperature=0`
  ในขั้นสกัด triplet และตั้งชื่อคลัสเตอร์ และจัดกลุ่มด้วยการโหวต Louvain 20 รอบ
- **ตัวเลขใช้กฎตายตัว** — สถานะเทรนด์, investment signal, Rank Score, Longevity และการคัด Top N คำนวณจากข้อมูลดิบ
  เพราะ walk-forward validation (n=186) พบว่ากฎจาก Z_Delta แม่น 63.4% ขณะที่ LLM ตัดสินเองแม่น 40.9%
- **การพยากรณ์ทำซ้ำได้** — ข้อมูลรายเดือนชุดเดิมให้ผลเดิม (รันซ้ำด้วยข้อมูลที่เก็บไว้ของรอบ 082438 ได้ `step5c` ตรงทุกค่า)
  แต่ถ้าดึง Google Trends ใหม่ ตัวเลขจะเปลี่ยนตามข้อมูลล่าสุด
- **การจับคู่สินค้ายังไม่เคยวัดความแม่นเทียบกับคน** — จับได้ดีกับเทรนด์ที่เป็นหมวดสินค้าชัด (เช่น กันแดด, ดูแลเส้นผม)
  แต่อ่อนกับเทรนด์เชิงเทคโนโลยีสูตรหรือเทรนด์ที่นิยามจากกลุ่มผู้ใช้ และค่า similarity ยังไม่มีเกณฑ์ตัดสิน —
  ใช้ผลเป็นรายชื่อตัวเลือกให้คนตรวจต่อ
