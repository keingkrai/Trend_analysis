### สาย Search (①-⑤ ตั้งแต่ 2026-10-27)

`tool/phase9_search_stream/search_stream.py` (ตัวแปรปรับค่าและข้อจำกัดอยู่ใน [README ของสายนี้](tool/phase9_search_stream/README.md)):

1. **ดึงคำค้นที่กำลังขึ้น** (`rising.py`) — Google Trends "Related queries → Rising" ของทุกหมวดระดับ 1-2 ไทย + ทั่วโลก ช่วง 12 เดือนล่าสุด
   (ระบุแค่หมวด ไม่ใส่คำค้น · 1 หมวด x 1 พื้นที่ = 1 search ของ SerpAPI · cache รายเดือนที่ `output/_checkpoints/search_rising/` ~600 search ต่อเดือน
   รอบอื่นในเดือนเดียวกันไม่เสียโควตา) รอบ 164405: 598 รายการ ได้คำค้นไม่ซ้ำ 10,701 คำ (Google ให้เฉพาะรายการที่ "ขึ้น" ไม่ใช่คำค้นทั้งหมด และไม่มีปริมาณการค้นหา)
2. **AI จัดหัวข้อ** (`themes.py`) — ต่อหมวดใหญ่ 2 รอบ: รอบแรกจัดเป็น 6-15 หัวข้อ (เรื่อง เหตุการณ์ หรือความต้องการ หัวข้อละ ≥ 3 คำ) รอบสองจัดคำที่เหลือเพิ่มไม่เกิน 20
   หัวข้อ ที่เข้าหัวข้อไม่ได้ลง "Other" · จัดตามเนื้อหา ไม่ตามหมวดที่ Google ใส่ (Google ใส่ผิดหมวดบ่อย) · จำนวนคำ / พื้นที่ / Breakout นับด้วยโค้ด รอบ 164405: 684 หัวข้อ
3. **AI โยงเครื่องสำอาง** — 7 ทางที่ตั้งไว้ล่วงหน้า (ความงามตรงๆ · สภาพแวดล้อม · ร่างกายและสุขภาพ · โอกาสและเทศกาล · กิจกรรมและไลฟ์สไตล์ · ส่วนผสมข้ามหมวด ·
   วัฒนธรรมและลุค) + หมวดสินค้า Euromonitor L2 (รายการปิด 13 หมวด) กฎในโค้ด: ต้องอ้างคำค้นตัวอย่างอย่างน้อย 1 คำ ไม่งั้นนับเป็นไม่โยง → รอบ 164405: 73 หัวข้อ
   (คำค้น 7.6%) **ข้อจำกัด:** กฎตรวจแค่ว่า "มีคำค้นอ้างเป็นหลักฐาน" ไม่ได้ตรวจว่าคำค้นนั้นพูดถึงความงาม ทางโยง 2-5 จึงเป็นการอนุมานทางอ้อมของ AI
   (เช่น มาราธอน → กันแดดกันเหงื่อ, ยาลดน้ำหนัก → ผิวหย่อนคล้อย) หลวมกว่าด่านหลังๆ
4. **เรียงด้วยกฎตัวเลข** (ขึ้นกี่พื้นที่ > มีไทย > จำนวนคำค้น > สัดส่วน Breakout) เอา 40 หัวข้อแรก (2 x `TREND_SEARCH_TOP_K`) → AI รวมหัวข้อที่เป็นความต้องการความงามเดียวกัน
   เป็นเทรนด์ ตั้งชื่อ (3-7 คำ ห้ามชื่อแบรนด์/คน/เหตุการณ์) และเขียน `search_keywords` 3-6 คำ (คำฝั่งความงามที่คนทั่วไปค้น — **คือคีย์เวิร์ดที่ ⑦ ใช้วัดการเติบโต
   เป็นคำที่ AI เสนอ ไม่ใช่คำค้นที่ขึ้นเอง**) กับ `product_keywords` 2-4 คำ (ชนิดสินค้า) รอบ 164405: 15 เทรนด์
5. **จุดตรวจ** `phase2_search_candidates.csv` — คอลัมน์ `keep` (1 = ใช้, 0 = ตัดทิ้ง) 20 อันดับแรกตั้ง 1 ไว้ รันแบบโต้ตอบจะหยุดให้แก้ก่อน ⑦ (ขั้นที่เสียโควตา)
6. เขียน `phase2_search_stream_result.json` รูปแบบเดียวกับผลของสายเดิม (⑦ เป็นต้นไปไม่ต้องแก้) + งานกลางทาง `search_stream_work/` (หัวข้อ / ผลโยง / โปรไฟล์เทรนด์)
   รันขั้นนี้ซ้ำในรอบเดิมใช้ต่อ ไม่ถาม LLM ซ้ำ — ลบไฟล์ในนั้นถ้าต้องการให้ทำใหม่

รายชื่อสายอยู่ที่เดียวใน `tool/common/streams.py` — แต่ละรอบใช้เฉพาะสายที่มีไฟล์ผล (รอบใหม่ = Search, รอบเก่า = 3 สายเดิม)
⑩ รอบค้นพบเพิ่มใช้กับ 3 สายเดิมเท่านั้น จึงไม่ถามในรอบใหม่

### สายหลักฐานเดิม (①-⑤ ก่อน 2026-10-27 — ไม่รันแล้ว)

ทั้ง 3 สายใช้โครงเดียวกัน ต่างกันแค่แหล่งข้อมูลและภาษาที่ใช้ค้น จึงเทียบกันได้ตรงๆ

| สาย | แหล่งข้อมูล | ตอบคำถาม |
|---|---|---|
| **Paper** | ScienceDaily, MDPI, OpenAlex, PubMed Central | กลไกและเทคโนโลยีอะไรกำลังมา |
| **Social** | Pantip, Reddit, YouTube | ผู้บริโภคเจอปัญหาอะไร พูดถึงอะไร |
| **News** | ข่าวไทย + ข่าวสากล (RSS ใน `config/rss_feeds.json` + Google News) | ตลาด/แบรนด์/กฎเกณฑ์ขยับไปทางไหน |

ขั้นตอนในแต่ละสาย: LLM สร้างคำค้น → รวบรวมบทความ → LLM เลือกชิ้นที่เกี่ยวข้อง → เขียนรายงานพร้อมอ้างอิง `(Ref N)` →
สกัด triplet ทีละเอกสาร **พร้อมประโยคหลักฐานที่โค้ดตรวจว่ามีอยู่จริง** → สร้างกราฟและจัดกลุ่ม (Louvain โหวต 20 รอบ) →
ตั้งชื่อเทรนด์ + ให้คะแนน Longevity → แตกคีย์เวิร์ดสำหรับค้น Google Trends — เก็บ 5 เทรนด์ต่อสาย

### ชั้นพยากรณ์และจัดอันดับ (⑦ ⑧-⑨ ⑥)

- **⑦ พยากรณ์** — ดึง Google Trends ทั่วโลกผ่าน SerpAPI แปลงเป็น z-score รายเดือน พยากรณ์ด้วย 4 โมเดล
  (Holt-Winters, Linear Regression, Random Forest, XGBoost) เลือกโมเดลจากความคลาดเคลื่อนบนช่วง holdout 6 เดือน
  แล้วคำนวณ **Z_Delta** = ค่าเฉลี่ยที่พยากรณ์ − ค่าปัจจุบัน สถานะตั้งด้วยเกณฑ์ตายตัว
  (> 0.8 Major Breakout, > 0.2 Rising, < −0.2 Fading, นอกนั้น Stable)
- **⑧-⑨ สรุประดับหมวด** — รวม Z_Delta เป็นภาพรวมต่อสายและทั้งหมด (เป็นผลสรุป ไม่มีขั้นอื่นอ่านต่อ)
- **⑥ Rank Score** (🆕 2026-09-30, 🆕 2026-10-02 ปีที่ 2, 🆕 2026-10-19 ปีที่ 3) — **คะแนนการเติบโตปีที่ 3** (ระยะสั้น = `common/horizons.SHORT_YEAR`) จาก `growth_score.py`: ความแรง = ค่าเฉลี่ยการค้นหาที่คาดในปีนั้น ÷
  ค่าเฉลี่ย 12 เดือนล่าสุด ผสมอันดับ momentum (การโตปีที่แล้ว) กับ RandomForest ที่ฝึกจากทุกคีย์เวิร์ดในอดีต ให้คะแนนเป็น
  percentile เทียบคีย์เวิร์ดทั้งหมดในรอบ (0.5 = ค่ากลางตลาด) คำนวณปีที่ 1-5 - backtest 2016-2022 ได้ Spearman ≈ 0.40-0.52
  (Z_Delta เดิม −0.20) ไม่มีโบนัสจำนวนสายแล้ว (ใช้ตัดสินกรณีเท่ากัน) ฝึกด้วยข้อมูลถึง `LAST_TRUSTED_MONTH` (มิ.ย. 2025)
  เพราะข้อมูล cat=0 กระโดดตั้งแต่ ส.ค. 2025 **ตอนนี้ใช้โมเดลอย่างเดียว** (`growth_score.BLEND_MOMENTUM = False`) เพราะช่วง
  กระโดดทำให้ momentum เพี้ยน คะแนนเทรนด์ = percentile ของ % ที่คาดของเทรนด์ ระดับกับ % ในรายงานจึงตรงกัน เปิดแบบผสมกลับเมื่อ
  ข้อมูลถึง ก.ค. 2027 (โปรแกรมเตือนให้เอง) กราฟหน้าเทรนด์แสดงระดับที่คาดปีที่ 1-5 พร้อมแถบ 80% จาก backtest (คลาดเฉลี่ย
  6% / 9% / 12% / 16% / 20%) และ (รอบ 3 สายเดิม) ปรับคะแนน Longevity ของเทรนด์ที่ยืนยันข้ามสาย — **รันหลัง ⑦ เพราะใช้
  ค่าการค้นหารายเดือน (step5a)**

### ชั้นอุปทาน (⑪ ⑫ ⑬)

- **⑪ จุดเด่น + Top N** — เดินตามอันดับ ⑥ (เฉพาะเทรนด์ที่คะแนนปีที่ 3 ถึง `GROWTH_LINE` = 0.5 = ค่ากลางตลาด) จนได้ N เทรนด์ที่จับคู่สินค้าได้ — **N คือเพดาน
  (ค่าเริ่มต้น 10) จำนวนที่ได้จริงอาจน้อยกว่า** ·  สกัดจุดเด่นของเทรนด์ 6 มิติ (Means-End Chain / Jobs to Be Done / Points-of-Parity-Difference):
  - **สาย Search** (`highlight_evidence.py`): AI อ่านคำค้นจริงของเทรนด์แล้วเขียนทีละมิติพร้อมคัดลอกคำค้นที่อาศัย 1-3 ข้อ **โค้ดตรวจ**: คำค้นต้องมีจริง, ตัวเลขและข้อความ
    ในเครื่องหมายคำพูดต้องอยู่ในหลักฐาน, ห้ามคำบอกเตรียมตัว/วางแผน/ความรู้สึกที่คำค้นไม่ได้บอก (`common/evidence_gate.py`) — มิติที่ไม่ผ่าน = "ข้อมูลไม่พอ"
    (เช่น คำค้นเป็นชื่อประกวด/ทีมกีฬา ไม่มีมิติไหนผ่าน) ผลบันทึกพร้อมคำค้นที่ยืนยันแล้ว (`evidence`)
  - 🆕 2026-10-28 **`beauty_need`** = ความต้องการความงามที่ AI อนุมานจาก ①-⑤ (ชนิดสินค้า `product_keywords` + ประโยชน์ `key_benefits` + ทางโยง + หมวดสินค้า ติด `source: ai_inferred`)
    แนบในโปรไฟล์ของเทรนด์สาย Search ทุกตัว (`highlight_evidence.beauty_need`) — **ทุกเทรนด์ของสาย Search จึงจับคู่สินค้าได้เสมอ** ไม่ถูกตัดเพราะ "ข้อมูลไม่พอ" อีก
  - รอบ 3 สายเดิม: LLM สกัดจากข้อความของสาย ข้ามเทรนด์ประเภทช่องทาง/พฤติกรรมการซื้อ หรือที่ไม่มีข้อความให้จับคู่ แล้วเลื่อนอันดับถัดไปขึ้นมา
  - ตรวจเพิ่มจนรู้ Top 5 ที่จับคู่ได้ของปีที่ 3 และปีที่ 5 บันทึกใน `checked_trends` / `extra_profiles` (⑫ ⑬ อ่านแค่ `profiles`) — ชุด `profiles` คือชุดเทรนด์เดียวที่ ⑫ ⑬ และรายงานใช้ร่วมกัน

  27,532 แถว เฉพาะหมวดความงาม 22,392 ชิ้น) เป็นเวกเตอร์ 2,048 มิติ เรียงด้วย cosine similarity เก็บ 15 อันดับแรกต่อเทรนด์ และให้ LLM เขียนเหตุผลสั้นๆ ให้ 5 อันดับแรก
  - **ข้อความจับคู่** (`match_supply.build_trend_matchable_text`): เทรนด์สาย Search = **ความต้องการความงามที่ AI อนุมาน** (ชนิดสินค้า + ประโยชน์) เป็นหลัก ตามด้วยข้อความจาก
    4 มิติที่ผ่านเกต ⑪ + คำค้นที่ยืนยันแล้ว (ไม่เกิน 12 คำ) · ทดลองกับรอบ 164405: ใช้ความต้องการอย่างเดียวได้สินค้าตรงหมวดแทบทุกเทรนด์ แต่ Daily Skincare ได้แปรงแต่งหน้า

    **`TREND_MATCH_BASIS=evidence`** = วิธีเดิม (ข้อความจากคำค้นอย่างเดียว; รอบ 3 สายเดิมไม่มี `beauty_need` จึงใช้วิธีนี้เสมอ) · `TREND_MATCH_QUOTES=0` = ไม่ต่อท้ายคำค้นที่ยืนยันแล้ว
  - **หมวดหลัก (L2)**: AI เลือก 1 หมวดของ Euromonitor ที่ร้านขายเพื่อรองรับเทรนด์ (`trend_category.py` เห็นความหมายของเทรนด์ + ความต้องการที่ AI อนุมาน + สินค้าที่ใกล้ที่สุดต่อหมวด)

    ⑯ แสดงหน้าแจ้งแทนสินค้า / ⑰ ไม่ให้เกรด / ⑳ ส่งธงไปด้วย (ใช้เกณฑ์นี้เพราะค่าความคล้ายสูงสุดตัวเดียวแยกผลที่ใช้ได้ออกจากที่ใช้ไม่ได้ไม่ได้ — Long-Wear 0.18 ใช้ได้ Body Contouring 0.23 ใช้ไม่ได้)
  - แยกหมวด (`by_category`, ไม่ใช้ LLM): ดูว่าสินค้า 1% แรกที่ใกล้ที่สุดอยู่หมวดไหน (**Level 2 ของ Euromonitor** ตาม `product/product_category.csv` และตลาดกรองเหลือ
    **L1 = Beauty and Personal Care** 22,392 ชิ้น) และ `phase3_l2_market_map.json.gz` (ความตรงเทรนด์ของสินค้าทุกชิ้นในหมวดหลัก - ใช้ทำหน้าสินค้าและเกรด) ·
    หมวดของสินค้าแต่ละชิ้นจัดโดย LLM ล่วงหน้า ดู `product/classify_products_llm.py` · รอบที่รันก่อนมีการแยกหมวด เติมได้ด้วย `validate_at_scale_nvidia.py --categories-only`

   ช่วงราคารวมจำกัดที่ [ต่ำสุด, สูงสุด] ของแบรนด์ — สินค้าตลาดที่ถูก/แพงกว่านี้ไม่ถูกเทียบ

Means-End 3 บรรทัด, เขียน/แปลข้อความระดับรายงาน, แปลเหตุผลสินค้าใน ⑰) ต่อท้ายด้วยกติกาภาษาง่ายจาก `plain_text.py` (`PLAIN_RULES_EN` / `PLAIN_RULES_TH`:
ประโยคสั้น คำธรรมดา ห้ามคำอย่าง YoY/CAGR/momentum ไม่ทับศัพท์วิชาการเป็นเสียงไทย เปอร์เซ็นต์ = คาดว่าค้นหาเปลี่ยนเทียบ 12 เดือนล่าสุดแบบสะสม ห้ามกลับทิศการเปรียบเทียบ)
และเพิ่มเลข `PROMPT_VERSION*` (cache เดิมถูกคำนวณใหม่อัตโนมัติ) สิ่งที่เพิ่ม:
- `plain_report_texts_en()` เขียน takeaway / market summary / personas ฉบับอังกฤษเป็นภาษาง่าย (ชื่อ mega trend/persona คงเดิม, cache คีย์ `plain_en`) ก่อนแปลไทย
- `plain_cleanup()` แทนศัพท์เฉพาะที่หลุดมา (language model, SKU, job-to-be-done ...) ในผล LLM และในเหตุผลจับคู่เดิมของ ⑫/⑬ ตอนทำรายงาน
- แปลไทยถามซ้ำ 1 ครั้งเมื่อคำตอบไม่ผ่านการตรวจ (หัวข้อยังเป็นอังกฤษ); `generate_match_reason` (⑫) ไม่ใช้ "job-to-be-done" แล้ว (มีผลกับรอบใหม่)
**ตรวจภาษาและทดสอบผู้อ่าน (ขั้น E, 2026-10-12)** - ตัวตรวจอัตโนมัติ + ชุดทดสอบกับผู้อ่านจริง:

```bash
python tool/phase6_pdf_report/lint_report_language.py                       # ทุกรอบใน output/ (ข้อความตายตัว + ข้อความ LLM + PDF)
python tool/phase6_pdf_report/lint_report_language.py --run <รอบ> --md lint.md --no-pdf
python tool/phase6_pdf_report/reader_test.py sheet --lang th                # สร้างใบคำถาม/เฉลย/ใบตอบ -> output/_reader_test/
python tool/phase6_pdf_report/reader_test.py score answers.csv --lang th --md result.md
```

- `lint_report_language.py` ไม่เรียก API: **ERROR** = คำต้องห้ามนอกภาคผนวก (YoY, SKU, โมเดลภาษา, similarity ...), ศัพท์ pipeline หลุด (⑬, `--flag`, `*.py`, `{ตัวแทนค่า}`, None/nan);
  **WARN** = ประโยคอังกฤษยาวเกิน 35 คำ / ไทยติดกันเกิน 110 ตัวอักษร / คำอังกฤษทั่วไปในข้อความไทยที่ไม่ใช่ชื่อหรือส่วนผสม (รายการอนุญาตมาจากชื่อเทรนด์/สินค้า/แบรนด์ของรอบ + `BASE_ALLOW`)
  ข้ามกติกาในภาคผนวก (คีย์ `method_*`/`m_*`/`notes_*` และหน้าที่ขึ้นต้น "ภาคผนวก"/"Appendix"); ตรวจเฉพาะเทรนด์ที่อยู่ในรอบ (ไม่ตรวจรายการค้างใน cache) และเฉพาะ PDF ที่ pipeline สร้าง; exit 1 เมื่อมี ERROR (`--strict` นับ WARN ด้วย)
- ผลรอบล่าสุด (2026-10-12): ข้อความตายตัว 0 ERROR / 0 WARN, PDF ทุกรอบ 0 ERROR; WARN ที่เหลือเป็นข้อความที่ LLM เขียน (ชื่อสารเคมีอังกฤษ ฯลฯ) ให้ DA ตัดสิน
- `reader_test.py`: คลังคำถามปรนัย 16 ข้อ (⑯ 6 / ⑰ 5 / ⑱ 5) ถามความหมายของข้อความหลักในรายงาน (ตัวเลข % ปีที่ 2, "ตรงเทรนด์อันดับ n", ราคาต่อปริมาณต่ำ/กลาง/สูง, เกรดภาพรวม, "ติด x% แรก (อันดับ n)" ฯลฯ)
  อ้างข้อความจริงจากตารางข้อความจึงตามไปเองเมื่อแก้ถ้อยคำ ผู้อ่าน 3-5 คน (ไม่ใช่นักวิเคราะห์) คนละ ~15 นาที ไม่อธิบายระหว่างทำ -> กรอกใบตอบ CSV (1 แถว/คน)
  ผ่านเมื่อตอบถูกรวม ≥ 80% และทุกข้อ ≥ 60% ข้อที่ไม่ผ่านบอกตัวลวงที่คนเลือกมากสุด + คีย์ข้อความที่ต้องเขียนใหม่ (`trend.*`, `brand.*`, `category.*`, `unit.*`)
  **ยังไม่ได้ทดสอบกับผู้อ่านจริง** - ต้องให้ DA/ทีมหาผู้อ่านและรันรอบแรก

## 🔁 ความคลาดเคลื่อนและข้อจำกัด

- **LLM ให้ผลต่างกันได้ในแต่ละรอบ** — ชื่อเทรนด์และคีย์เวิร์ดอาจไม่เหมือนเดิมแม้ใช้หัวข้อเดิม ลดผลนี้ด้วย `temperature=0`
  ในขั้นสกัด triplet และตั้งชื่อคลัสเตอร์ และจัดกลุ่มด้วยการโหวต Louvain 20 รอบ
- **ตัวเลขใช้กฎตายตัว** — สถานะเทรนด์, investment signal, Rank Score, Longevity และการคัด Top N คำนวณจากข้อมูลดิบ
  เพราะ walk-forward validation (n=186) พบว่ากฎจาก Z_Delta แม่น 63.4% ขณะที่ LLM ตัดสินเองแม่น 40.9%
- **การพยากรณ์ทำซ้ำได้** — ข้อมูลรายเดือนชุดเดิมให้ผลเดิม (รันซ้ำด้วยข้อมูลที่เก็บไว้ของรอบ 082438 ได้ `step5c` ตรงทุกค่า)
  แต่ถ้าดึง Google Trends ใหม่ ตัวเลขจะเปลี่ยนตามข้อมูลล่าสุด
- **ที่มาของเทรนด์ในสาย Search เป็นการอนุมานหลายชั้น** — ขั้นโยงเครื่องสำอาง (①) ตรวจแค่ว่ามีคำค้นอ้างเป็นหลักฐาน ไม่ได้ตรวจว่าคำค้นนั้นพูดถึงความงาม และทางโยง 2-5
  (สภาพแวดล้อม ร่างกายและสุขภาพ โอกาส กิจกรรม) เป็นการอนุมานทางอ้อม เทรนด์บางตัว (เช่น มาราธอน/จักรยาน, ยาลดน้ำหนัก) จึงโยงเข้าความงามด้วย AI อนุมานเอง ตัวเลขการเติบโตวัดจากคีย์เวิร์ดความงามที่ AI เสนอ
  ไม่ใช่คำค้นที่ขึ้นเอง · คำค้นที่อยู่ในหัวข้อที่โยงมีราว 7-8% ของทั้งหมด · การรวมหัวข้อเป็นเทรนด์หลวมได้ (เช่น เกมแต่งตัวตุ๊กตาเข้าเทรนด์สกินแคร์)
- **การจับคู่สินค้าของสาย Search ใช้ "ความต้องการความงามที่ AI อนุมาน" เป็นหลัก** — ไม่ใช่สิ่งที่คนค้นหาตรงๆ ตั้ง `TREND_MATCH_BASIS=evidence` เพื่อกลับไปจับคู่จากคำค้นอย่างเดียว
  หน้าสินค้าและหน้า Methodology ของรายงานบอกเรื่องนี้ ; รายงานแบรนด์ (⑬ ⑰) ใช้ข้อความจับคู่ชุดเดียวกันแต่ยังไม่มีป้ายบอก และต้องรันใหม่เมื่อเปลี่ยนฐานจับคู่ ;

- **การจับคู่สินค้ายังไม่เคยวัดความแม่นเทียบกับคน** — จับได้ดีกับเทรนด์ที่เป็นหมวดสินค้าชัด (เช่น กันแดด, ดูแลเส้นผม)
  แต่อ่อนกับเทรนด์เชิงเทคโนโลยีสูตรหรือเทรนด์ที่นิยามจากกลุ่มผู้ใช้ และค่า similarity ยังไม่มีเกณฑ์ตัดสิน (ใช้กฎ "5 ชิ้นแรกอยู่ในหมวดหลักกี่ชิ้น" ตัดสินว่าแสดงสินค้าหรือไม่) —
  ใช้ผลเป็นรายชื่อตัวเลือกให้คนตรวจต่อ
- **ข้อความที่ AI เขียนในรายงานตรวจได้เฉพาะตัวเลข คำค้นที่ยก และรายการคำต้องห้าม** — ถ้อยคำอื่นตรวจด้วยโค้ดไม่ได้ ฉบับไทยอาจมีคำพิมพ์ผิด ควรให้คนอ่านทวนก่อนส่ง

## 🛠️ การพัฒนาต่อ

- **ใช้ `common/bootstrap.py` หา path เสมอ** (`PROJECT_ROOT` = โฟลเดอร์บนสุดของ repo, `TOOL_DIR`, `OUTPUTS`, `CHECKPOINTS`) — ห้ามเขียน path ตายตัว
- **ผลเฉพาะรอบเขียนลง `OUTPUTS`** ส่วน cache ที่ไม่ขึ้นกับหัวข้อเขียนลง `CHECKPOINTS` (ถ้าใช้ `OUTPUTS` จะถูกสร้างใหม่ทุกรอบ)
- **ใช้ `safe_json_parse` จาก `common.bootstrap`** เมื่อ parse คำตอบของ LLM
- **เพิ่มขั้นใหม่** — ใส่ใน `STAGES` ของ `main.py` และลงไฟล์ input/output ใน `STAGE_IO_MAP` ของ `bootstrap.py` เพื่อให้ manifest ครบ
- **`common/trend_final_subset.py` / `trend_final_v2_subset.py`** เป็นสำเนาตรงตัวของต้นฉบับ ทุกบล็อกมีป้ายบรรทัดต้นฉบับ
  ถ้าจะแก้บล็อกไหน ให้ใส่ `⚠️ แก้จากต้นฉบับ: <เหตุผล>` ในป้าย ไม่อย่างนั้นเทสต์จะฟ้อง (ต้นฉบับไม่อยู่ใน repo —
  เทสต์ที่ต้องเทียบกับต้นฉบับจะข้ามเองถ้าไม่พบไฟล์)
- **รันเทสต์ก่อน commit**

```powershell
python -m pytest tool/tests -q                                          # ~1-1.5 นาที (676 ข้อ ข้าม 1) ไม่เรียก API
$env:TREND_SUBSET_FULL="1"; python -m pytest tool/tests/test_trend_final_subset.py   # + เทียบพยากรณ์เต็ม ~15 นาที
```
